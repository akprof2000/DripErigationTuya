# Повторение проекта с нуля: от пустого аккаунта до полива в облаке

Пошаговая инструкция для тех, кто хочет собрать такой же контроллер у себя.
Пройдя все шаги, получите: ESP32 с нашей прошивкой, устройство в Smart Life
со своей панелью на русском, push-уведомления, OTA-обновления и (опционально)
управление голосом через Алису.

Время: ~2–3 часа без учёта пайки и доставки лицензии.

---

## 0. Что понадобится

| Что | Комментарий |
|---|---|
| ESP32 DevKitC (38 pin) | лучше версия с внешней антенной — на даче сигнал слабый |
| Плата-носитель и обвязка | схема, KiCad, BOM и сборка — в [DripIrrigation](https://github.com/akprof2000/DripIrrigation) (этот проект использует то же железо без изменений) |
| Аккаунт на [platform.tuya.com](https://platform.tuya.com) | бесплатный; дата-центр выбирайте Central Europe (для России/Европы) |
| Приложение **Smart Life** на телефоне | регион аккаунта — тот же дата-центр |
| Python 3.11+, Node.js 18+ | для сборки прошивки и панели |
| [Tuya MiniApp IDE](https://platform.tuya.com/download/miniapp/devtool) | для загрузки панели |
| Лицензия TuyaOpen (UUID + AuthKey) | 2 шт. бесплатно на продукт — шаг 3 |

Ключевой момент: **в прошивке нет никаких ключей**. Она заработает на любой
ESP32, но облако требует лицензию на каждое устройство (UUID + AuthKey) —
её вы получите на своём продукте и положите на плату файлом `tuya.json`.

## 1. Создать продукт в консоли Tuya

1. [platform.tuya.com](https://platform.tuya.com) → регистрация/вход.
2. Слева **AI Product** → (или «Development» в Recently Visited) → **Create**.
3. Тип: **Custom** (внизу списка категорий, «Can't find the category?» →
   «Custom») → любая категория-заглушка, у нас «Others».
4. Протокол: **Wi-Fi + Bluetooth LE**.
5. Имя: любое (у нас «Drip Irrigation 8ch») → **Create**.
6. После создания на странице продукта запишите **PID** (вида `0uo7xxxxxxxxxxlgp`) —
   он понадобится везде дальше.

## 2. Точки данных (DP)

В консоли у продукта: вкладка **Function Definition** → отключить стандартные
функции → **Add custom DP** для каждой точки из спецификации.

Полный список (70 DP: 8 грядок, вода, расходомер, сервисные, имена грядок,
справочник растений) — в таблице [dp.md](dp.md), машиночитаемый источник —
[../spec/dp.json](../spec/dp.json). Из этого же файла генерируются таблицы
прошивки и панели, поэтому ID, типы и диапазоны должны совпадать **один в один**:
value/enum/bool, min/max/scale — как в таблице.

> Проверка: в прошивке DP собраны в `firmware/esp32/include/dptab.h`
> (`python tools/gen_dptab.py` пересоздаёт её из `spec/dp.json`). Если в консоли
> DP отличается — панель и команды будут молча «промахиваться».

## 3. Железо продукта и лицензия (UUID + AuthKey)

Лицензия — это ключ устройства к облаку: **одна пара UUID+AuthKey = одно
устройство**, переносить на другую плату нельзя.

1. У продукта: вкладка **Hardware Development** → выбрать модуль **T5-E1**
   (заглушка; реальный чип — ваш ESP32, консоли без разницы) →
   **Add Custom Firmware**, загрузить любой файл-заглушку.
2. После этого на странице продукта появится возможность **бесплатно получить
   2 авторизационных кода** (Claim free authorization codes) — заберите их.
3. **Purchase → Licenses** (или [страница лицензий](https://platform.tuya.com/purchase/index?type=6))
   → в списке лицензий скопируйте **UUID** и **AuthKey**. Нужны больше двух —
   там же покупаются (~$0.69 за устройство).
4. Создайте файл лицензии:

```bash
copy emulator\tuya.example.json emulator\tuya.json   # Windows
# вписать в него pid (шаг 1), uuid и authkey (шаг 3.3)
```

## 4. Собрать и прошить ESP32

```bash
git clone https://github.com/akprof2000/DripErigationTuya.git
cd DripErigationTuya
python -m venv .venv
.venv/Scripts/python -m pip install -r emulator/requirements.txt platformio

.venv/Scripts/python tools/deploy.py --build                      # сборка → firmware/dist/drip_<версия>.bin
.venv/Scripts/python tools/deploy.py --port COM8 --upload         # прошить (порт подставить свой)
.venv/Scripts/python tools/deploy.py --port COM8 --fs --creds     # записать tuya.json в LittleFS
.venv/Scripts/python tools/deploy.py --port COM8 --monitor        # консоль платы
```

Плата без автосброса: перед заливкой зажать **BOOT** и кратко нажать **EN**.

Либо без сборки: готовый `drip_<версия>.bin` берите из
[релизов](https://github.com/akprof2000/DripErigationTuya/releases) и шейте
esptool (`esptool.py --port COM8 write_flash 0x10000 drip_<версия>.bin`),
затем шаг `--fs --creds` обязателен.

## 5. Wi-Fi и привязка к Smart Life

1. Включите плату. Если сети нет в памяти (или зажать кнопку на 5 с) — поднимется
   открытая точка доступа **`DripIrrigation-XXXX`**.
2. Подключитесь к ней телефоном → откроется портал (иначе `http://192.168.4.1`)
   → выберите свою сеть **2,4 ГГц**, введите пароль.
3. На странице портала показывается **QR-код привязки**.
4. Smart Life → «+» → «Добавить устройство» → сканировать QR → устройство
   появится в приложении (активируется само за ~10–20 секунд).
5. Светодиод на плате: горит — на связи с облаком; мигает раз в секунду — Wi-Fi
   есть, облака нет; частое мигание — нет Wi-Fi.

Полив работает и без облака — облако нужно для приложения, графиков, пушей и OTA.

## 6. Панель устройства

Стандартная панель Tuya наши 70 DP не покажет — нужна своя (папка `panel/`):

1. [MiniApp Developer Platform](https://platform.tuya.com/miniapp) →
   **Create MiniApp** → тип **Panel** → привязать к вашему PID. Запишите
   MiniApp ID и впишите его в `panel/project.tuya.json`.
2. `cd panel && npm install`.
3. Открыть папку `panel/` в **Tuya MiniApp IDE** → войти тем же аккаунтом →
   Plugins → **Panel Tools** → выбрать виртуальное устройство продукта → отладка.
4. Проверили → **Upload** в IDE → в консоли продукта: **Device Interaction** →
   выбрать эту панель как панель устройства.
5. Графики влажности/расхода берут облачную статистику DP — включите её:
   продукт → **Data** (или Cloud → Statistics) → включить статистику для
   DP **108** и **131–138**.

## 7. Push-уведомления

Консоль → продукт → **Device Notification**, создать правила (тексты на русском,
английском, китайском):

| Правило | Условие |
|---|---|
| Засор фильтра | DP `fault` содержит `filter_clog` |
| Авария платы клапанов | DP `fault` содержит `valves` |
| Контроллер не в сети | устройство offline больше 30 минут |
| Грядка пересохла | DP `alert` (179) |
| Нет потока воды | DP `alert` (179) |

## 8. OTA — обновление по воздуху

1. Поднять `FW_VERSION` в `firmware/esp32/platformio.ini`, собрать
   (`deploy.py --build` печатает размер и md5).
2. Консоль → продукт → **Firmware Management** → ваша прошивка →
   **Add Firmware Version**: номер, файл `drip_<версия>.bin` в поле
   **Firmware Updates**, примечание → **Save & Enabled** → **Enable**.
3. **Firmware Update** → **New Update Deployment**: выбрать версию, метод
   **Forced Update** + **Auto Update** (автообновление без подтверждения)
   или **Update Notification** (кнопка в приложении) → OK → **Release** →
   100 % (Full amount).
4. Плата сама скачает образ во второй OTA-раздел, сверит md5 и перезагрузится;
   если новая прошивка минуту не вышла на связь — загрузчик откатит на старую.

## 9. Алиса (опционально)

Голосовое управление и датчики в «Доме с Алисой» — отдельная функция Яндекс
Облака: инструкция в [../alice/README.md](../alice/README.md)
(Cloud Project в Tuya с Access ID/Secret → функция Python → API Gateway →
навык «Умный дом» → таймер для уведомлений).

## 10. Эмулятор — проверить всё без железа

```bash
cd emulator
../.venv/Scripts/python main.py --offline     # чистая логика, без облака
../.venv/Scripts/python main.py               # с облаком: расходует вторую лицензию
```

Эмулятор — то же устройство в приложении Smart Life: удобно гонять панель,
команды и OTA-консоль, не трогая плату. Тесты логики:
`cd emulator && python -m unittest discover -s tests` (53 теста).
